# md-memory

把你的本地 **Markdown 文件**变成 AI 助手的常驻记忆。

**它不存储记忆、不提炼、不检索正文。** 记忆本身住在你自己的 `.md` 文件里，这个插件只做两件事：

| 它做的 | 说人话 |
|---|---|
| 每轮把「规则」目录下的文件**全文注入系统提示** | 你写在纸上的规矩，每次开口前都摆在 AI 眼前，一条不落 |
| 你提到某个领域时，塞一张**便条**说"去翻哪个文件" | AI 自己按路径去查，资料正文不占上下文 |

> **验证范围**：目前**只在 DSH 上验证过**（Windows）。其他宿主/平台未测试。

---

## 它解决什么问题

大多数「AI 记忆插件」是这样的：自动采集 → 蒸馏 → 检索 → 每轮挑几条注入。

问题是：**「挑」这个动作会淘汰东西，而且是静默的。**

一个真实案例（一个自用系统）：库里有**上百条**记忆，达到注入门槛的约**三分之一**，但每轮名额只有**二十条** —— 于是有一批被**静默挤掉，模型完全看不见**。排序键里带"更新时间"，于是**最新写的几条补丁式条目，把更早写下的最关键约束挤了出去**。

结果是一种很怪的局面：规则确实存在、AI 也确实"知道"，但每轮就是没进上下文。

这个插件的立场是：**记忆该留哪条，由你决定，不该由插件的排序算法决定。**

---

## 不适合谁

- **还没有 md 笔记的人**：你没有任何东西可注入，装了也是空的。
- **想让 AI 自己攒记忆的人**：它没有写入通道，一个字都存不进去。

**适合**：已经有一堆 md 笔记 / `AGENTS.md` / Obsidian 库，但发现 AI 从来不去读的人。

## 安装

```bash
dsh plugin --profile <你的 profile> add github:<owner>/md-memory
```

或本机路径（开发时）：

```bash
dsh plugin --profile desktop add link:<本仓库绝对路径>
```

装完**重启 dsh**。

---

## 配置

**不要改源码。** 在你 profile 的 `cordis.patch.yml` 里给这行加 `config`：

```yaml
- id: md-memory
  config:
    memoryRoot: 'D:\notes\memory'      # ← 你的记忆库根目录
    rulesDir: 'rules'                  # 每轮全量注入的目录（默认 rules）
    indexFile: 'INDEX.md'              # 路由表文件（默认 INDEX.md）
    topicsDir: 'topics'                # 路由目标所在目录（默认 topics）
```

| 字段 | 默认 | 说明 |
|---|---|---|
| `memoryRoot` | **空** | **必填**。留空 = 插件不启用，系统提示里只留一行说明 |
| `rulesDir` | `rules` | 每轮全量注入的目录，相对 `memoryRoot`；也可写绝对路径 |
| `rulesFiles` | 空 | 指定具体文件（相对 `rulesDir`）；留空 = 扫目录下所有 `*.md`，按文件名排序 |
| `indexFile` | `INDEX.md` | 路由表来源，相对 `memoryRoot` |
| `topicsDir` | `topics` | 路由目标短名会在这个目录下找 |
| `maxBytesPerFile` | `12000` | 单文件字节上限 |
| `maxBytesTotal` | `32000` | 合计上限 |

改完重启 dsh 生效。超预算会在注入内容里明写 `[已截断到第 N 行]`，不会静默截断。

### 目录长什么样

```
D:\notes\memory\
├─ INDEX.md          ← 路由表
├─ rules\            ← 每轮全量注入
│    01_style.md
│    02_safety.md
└─ topics\           ← 按需查，不注入正文
     deploy.md
     database.md
     debug.md
```

### 路由表格式

`INDEX.md` 里要有一张这样的表，插件**只认这一张**（按表头定位）：

```markdown
| 听到这些 | 取这个文件 |
|---|---|
| 部署 / 上线 / 发版 | `deploy` |
| 数据库 / 迁移 / schema | `database` |
| 报错 / 崩溃 / 异常 | `debug` |
```

## 验证装好了没

```bash
node test-offline.mjs
```

它不加载 dsh、**只读仓库自带的 `test-fixtures/` 示例数据**，跑 10 项检查：

- 未配置时：提示"未配置 memoryRoot"，路由命中 0 条
- 配了示例目录：2 个规则文件都读到、不触发截断
- 5 句触发用例：该命中的命中，该拦的拦住

**这一步不通过就别装。**

装好后的真实验证：新开一个对话，看系统提示里有没有 `rulesDir` 下那些文件的全文（DSH 的 Trajectory 里能看到）。

## 设计取舍

| 决定 | 为什么 |
|---|---|
| **零依赖**（不 import 任何 `@deepseek-ai/*`） | peer 缺失会让整条插件静默不激活，最难排查 |
| **只读，没有写入通道** | 仓库里搜不到 `writeFile`。写入权在你 |
| **规则走 `systemPrompt.section`，路由走 `context`** | section 每轮都在，天然不受上下文压缩影响 |
| **任何异常只降级、不抛错** | 文件被改名/删掉 → 显示"读不到，已跳过"，会话照常 |
| **不做向量、不做提炼、不做 UI** | 那些是"记忆引擎"的事，这个不是引擎 |

## 已知局限

- **文件要你自己维护**：它不会帮你写任何东西。
- **中文按字匹配**：单字（如"改"）也会命中，靠一份废字黑名单挡掉"的/了/是"这类。可能偶尔多提醒一次——**宁可吵，不许漏**。
- **只有一个人维护**，出问题得自己改。
- **只在 DSH + Windows 上验证过**。
